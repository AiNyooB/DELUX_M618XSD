# ADR: 快捷指令页（宏管理）Phase 5 实现决策

- **状态**：已采纳（Accepted）
- **日期**：2026-08-17
- **修订**：2026-08-18（按用户确认的协议事实与当前代码修订：宏内容**不写设备**——官方驱动同样不支持独立宏写入，宏仅经改键页绑定按键后生效；同步修正 Esc 录制语义、删除两步确认、录制去重/步数上限等实现细节。以修订后内容为准）
- **决策人**：用户 + AI 代理
- **相关代码**：`DELUX.Driver/Views/MacroPage.xaml`（左列表 + 右编辑器）、`AppViewModel.cs`（宏管理区：`MacroItem`/`MacroActionItem`/列表管理/录制/保存管线）、`KeyboardRecorder.cs`（WH_KEYBOARD_LL 键盘钩子）、`Models.cs`（`MacroConfig`/`MacroAction`/`BuildMacroChunks`，1:1 移植 MouseDriverClient 实机验证版）、`Core/IntEqualsConverter.cs`

---

## 1. 背景 / 问题

Phase 4 的宏绑定只写「宏 ID」占位，宏内容（录制/编辑/播放方式）无实现，绑定后设备侧没有实际动作序列。Phase 5 要把宏管理做成闭环：**录制动作序列 → 选绑按钮 → 写入设备**。

计划文档列了完整功能清单（命名/新建/删除/复制、录制 Hook、动作表、播放方式、导入导出、原始字节、未绑定警告），但存在几处协议事实与计划假设的冲突，需要先定语义再落地。

> 修订注：初版 ADR 曾假设「宏页保存 = 防抖 1.5s → 0x0C 唤醒 + 0x09×3 分块写设备」。实机/官方软件对照后确认：**官方驱动不提供独立宏写入（无 0x09 直写入口）**，宏只能在改键页把按键绑定为宏后由设备按绑定生效。故宏页保存管线改为「仅本地持久化」，详见 2.6。

---

## 2. 决策

### 2.1 延迟语义：直接按「设备实际生效延迟」输入（不用 Phase 2 的 PC 输入换算）

- 协议事实（HID协议逆向报告.md 3.6，2026-08-09 实测修正）：flag|delay 字节的 bits0-6 是延迟编码，**设备端解码为 `max(10ms, byte×5ms)`，不是 byte×100ms**。Phase 2 的 `EncodeDelay`（`round(ms/100)`）只能正确编码 PC 输入值，设备实际延迟只有其 1/20——「填 1000ms 实际 50ms」的困惑源头。
- 决策：UI 一律输入**设备实际生效延迟**，`byte = clamp(round(ms/5), 1, 127)`（10..635ms 按 5ms 取整，与设备解码严格互逆）；`PcInputToActualMs` 保留作参考，不走主路径。`MacroAction.DelayMs` 语义从「PC 输入」改为「设备实际」。
- 附带：动作行的「延迟」就是 flag 里的延迟位（`[keycode, flag|delay]` 对），**不做独立的延时动作行**（131B 缓冲没有纯延迟记录格式）。

### 2.2 设备槽位固定 1..6（非计划写的 0~5）

- 0x08 按键映射 `entry[2]` 的宏 ID 与 0x09 宏头 `buf[2]` 用的是同一套 ID，现有代码与实机验证均按 1..6（`entry[2] >= 1 && entry[2] <= 6`）。计划文档「ID 0~5」为笔误，以协议与实现为准：**槽位 1..6，0 = 未分配**。
- 上位机按「可命名宏列表」管理（`MacroItem`），保存时把未分配宏映射到空闲槽位；名称↔槽位映射随 `macros.json` 本地持久化。删除宏即释放槽位（设备上旧数据保留到被覆盖，不主动写空宏——空宏编码未验证，不盲发）。

### 2.3 鼠标动作：不提供入口（未验证 → 等待协议补齐）

- 计划要求「鼠标动作码未验证则置灰 + 等待协议补齐」。实查 `reference/parse_macro*.py`：鼠标键码在宏中全是问号（未验证），故**整个「插入鼠标」入口都不出现**，录制/插入仅收录键盘键码（`KeyboardRecorder.VkToHid` 白名单）。绝不盲发未验证编码。
- 若未来验证鼠标码，只需扩展 `VkToHid` 等价的键码表 + 在动作行加类型列。

### 2.4 录制用自研低级键盘钩子（WH_KEYBOARD_LL），零第三方依赖

- 不引入 `globalmousekeyhook` 等 NuGet（AGENTS.md 约定）；`KeyboardRecorder` 用 `SetWindowsHookEx(WH_KEYBOARD_LL)` P/Invoke。回调在安装线程（WPF UI 线程）的消息循环触发，事件可直接改 UI。
- **生命周期**：仅录制/「插入按键」捕获态安装，结束/取消即卸载；页面 `Unloaded` 兜底 `CancelCapture`，防导航后常驻。
- **录制规则**：按下/抬起都入列；相邻事件间隔 → 前一个动作的延迟（设备实际，10..635ms 按 5 取整）；**Esc 作为普通按键入列**（宏需要 Esc 场景；仅「插入按键」捕获态用 Esc 取消捕获，Esc 本身不入列——修订：初版「Esc 结束录制」与宏内需要 Esc 冲突，已改为 Esc 正常录制）。
- **防呆**：
  - 长按按键的系统 auto-repeat 事件去重（同键未抬起前的重复 down 忽略），避免按住 1s 录进数十个重复「按下」；
  - 停止录制时补录仍按住的键为「抬起」（停止瞬间物理抬起已收不到，防播放时修饰键/按键卡死）；
  - 单宏步数上限 **49**（0x09 数据区 [30..128] 上限，见 2.6/4），录制达到上限自动停止并提示；
  - 录制会追加到当前序列末尾（不覆盖，防误清）。
- **录制/编辑/保存均为纯本地操作，不要求设备连接**（宏不写设备，见 2.6）。

### 2.5 编辑器为「选中即编辑」单视图（未做原型 §4.2 的两步）

- 原型是「列表 + 摘要 → 点编辑进抽屉」两步；为减少点击、降低普通用户认知负担，改为**选中左侧宏即进入右侧编辑器**（名称框、录制/插入/重置/删除、动作表、播放方式、原始字节全在一屏）。列表副行摘要（步骤数 · 播放方式）+ 已绑定徽章保留概览信息。
- 删除/清空为**两步确认**（按钮文案变「确认删除？/确认清空？」，2.5s 未再点自动解除），满足 AGENTS.md「危险操作二次确认」。
- 删除的两次点击按**目标宏 Id** 记武装（武装 A 后再点 B 的删除，只会把武装切到 B，不会误删 B）；删除**第一击不进入编辑态**（初版先 `SelectMacro` 再武装，选中即禁用左栏导致第二击点不到，删除死锁——已修）。

### 2.6 保存管线：仅本地持久化，不写设备（官方驱动同样不支持独立宏写入）

- **宏内容不通过快捷指令页写入鼠标**：官方驱动不提供独立宏写入（无 0x09 直写入口），宏只能在「改键设置」页把按键绑定为宏（0x08 `entry[0]=0x12`、`entry[2]=槽位`）后，由设备按绑定关系生效。故宏页点「保存」**仅落本地 `macros.json` + 分配槽位，不 WriteFeature、不要求连接设备**。
- 因此不存在「1.5s 防抖 → 0x0C 唤醒 → 0x09×3 分块」的自动写设备管线；宏页保留显式「保存」按钮（用户期望显式确认后再落盘），保存成功 Toast 提示「已保存到本机，在『按键设置』绑定到按键后即可生效」。
- 未连接 / 官方驱动运行均**不影响**录制、编辑、保存（均为本地操作）；改键页写设备路径仍受官方驱动拦截约束。
- **未保存提示**：关闭编辑器（✕ `CloseMacro_Click`）或切页导航（`MainWindow.Navigate`）时，若 `SaveStatusText == "未保存"` 弹二次确认（保存并关闭 / 丢弃 / 取消），满足 AGENTS.md 3.4「切页前确认，不丢用户输入」。**「丢弃」= 真正回滚**：进入编辑态时对宏配置深拷贝快照（`EditingMacro` setter → `CloneConfig`），丢弃时 `DiscardMacro()` 恢复到快照（改名/播放方式/循环次数/动作序列含延迟全回滚，列表同步刷新）；保存成功后快照刷新为本次保存状态——丢弃目标是**最近一次保存**而非进入编辑时。
- 编辑器任何修改（名称/播放方式/循环次数/动作/延迟）都须置 `SaveStatusText = "未保存"`——延迟框直改共享 `MacroAction` 对象，经 `MacroActionItem.DelayChanged` 事件回补标记（历史缺陷：改延迟不出现「未保存」，关闭后静默丢失）。

### 2.7 改键页宏 Tab 与宏页选中态分离（`IsBindingSelected` vs `IsSelected`）

- 改键页宏 Tab 的勾选 = **当前按钮绑定的宏 ID**；宏页左侧列表的勾选 = **正在编辑哪个宏**。初版共用 `MacroItem.IsSelected`，两处互斥逻辑会互相覆盖（编辑宏 3 会改变绑定勾选）。
- 决策：`MacroItem` 增加独立 `IsBindingSelected`（改键页 Tab 绑定），`IsSelected` 专属宏页编辑选中。

## 3. 替代方案（被否决）

| 方案 | 内容 | 否决理由 |
|---|---|---|
| 宏页直接写 0x09 分块 | 点「保存」即 0x0C 唤醒 + 3×64 分块写设备 | 官方驱动同样不支持独立宏写入；宏只能经改键绑定生效。宏页写设备既无入口也无必要 |
| 沿用 Phase 2 延迟语义（PC 输入 + `EncodeDelay`） | UI 填 PC 延迟，编码 `round(ms/100)` | 设备实际只有输入的 1/20，「填 1000 实际 50ms」，计划明确要求按设备实际标注 |
| 录制用 `globalmousekeyhook` 等 NuGet | 现成键鼠钩子库 | 违反 AGENTS.md「不引入未列入计划文档的第三方库」；P/Invoke 30 行可等价实现 |
| 编辑器两步（摘要 → 抽屉） | 照抄原型 §4.2 | 多一步点击；单视图信息不丢且更直白（记录于计划文档偏差节） |
| 删除宏时同步清设备槽（写空 0x09） | 释放槽位时覆盖设备旧数据 | 空宏编码未验证，盲发有损坏配置风险；且本软件不写 0x09，设备槽内容由官方软件维护，仅提示「按键将指向空宏」 |

## 4. 影响 / 后续

- **持久化**：`macros.json`（LocalApplicationData/DELUX.Driver）保存 6 槽宏全量；与 `buttons.json` 并列，跨重启不丢。
- **可测性**：`MacroConfig.BuildCommandBuffer`/`BuildMacroChunks` 与 MouseDriverClient 实机验证版 1:1 移植（`MouseDriverClient.Tests/MacroConfigTests.cs` golden 覆盖 Phase 2 版；DELUX.Driver 侧暂无测试工程，建议后续为 `MacroConfig`/`MacroActionItem.NormalizeDelay`/`KeyboardRecorder.KeyNameOf` 补单测）。
- **未决/注意**：① 删除已绑定宏不改写 0x08 按键表（整表覆写风险，AGENTSK 6 节），只提示「按键将无动作」；② 录制延迟上限 635ms/步，超长间隔会被 clamp（协议上限，UI 提示常驻）；③ 步数上限 49 对（0x09 数据区 [30..128]），录制/插入/导入统一封顶（导入超限截断并提示）；④ 宏槽 0x09 内容在设备端不可读，且本软件从不写 0x09——设备宏槽内容仅由官方软件维护，删除宏不影响设备槽。
- **扩展**：导入/导出 JSON 结构（`{name, method, loopCount, actions:[{code,press,delayMs}]}`）即持久化格式的子集；后续 Profile（Phase 7）可直接复用 `Macros` 序列化。

## 5. 验证（Windows 实机）

- 新建宏 → 点「开始录制」→ 按键序列实时入列（按下/抬起成对，间隔自动填充延迟；长按不产生重复 down；Esc 正常入列）→ 点「停止录制」→ 按钮恢复品牌色，仍按住的键自动补「抬起」；改延迟/播放方式/名称后保存按钮出现「未保存」角标，点「保存」落本地 `macros.json`。
- **宏页不写设备**：录制/编辑/保存全程无设备 I/O（未连接鼠标也可完成）；保存 Toast「已保存到本机，在『按键设置』绑定到按键后即可生效」。
- 改键页把某键绑为「宏 + 该宏」→ 宏页列表该项出现「已绑定」徽章；0x08 整表覆写把绑定写入设备（宏内容不单独写 0x09）。
- 复制/删除（两步确认，武装按目标记；删除第一击不进入编辑态）/导入（非法 JSON 弹「文件无法识别」且不写入；>49 步截断并提示）/导出往返一致；重启软件宏列表与名称/槽位映射不丢。
- 录制中导航到其它页 → 钩子卸载（无残留钩子）；有未保存修改时关闭编辑器或切页均弹「保存并关闭 / 丢弃 / 取消」。
